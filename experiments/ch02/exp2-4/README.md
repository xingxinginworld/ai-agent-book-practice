# 实验 2-4：提示工程的消融实验

> 对应《深入理解 AI Agent》第 2 章 · 上下文工程 · 实验 2-4（原书目录名 `ablation`）
> 本仓库版本：**轻量本地可跑**，推荐本地 Ollama（`qwen3:0.6b`，免费、无限额、离线），也支持任意 OpenAI 兼容端点（AMD Radeon Cloud 等）。

## 〇、推荐：本地 Ollama 跑法

本实验首选本地 Ollama，理由同 2-3：模型你本来就有（2-2 用过 `Qwen3-0.6B`）、无需联网、无 429 限额、输出可确定性解析。

### 前置准备
```bash
# 1) 安装并启动 Ollama，确认服务在 http://localhost:11434
curl http://localhost:11434/api/tags
# 2) 拉取本地模型（若已下过可跳过）
ollama pull qwen3:0.6b
```

### 配置 .env（变量名与 AMD 路径完全一致，只改值）
```env
OPENAI_API_KEY=ollama
OPENAI_BASE_URL=http://127.0.0.1:11434/v1
OPENAI_MODEL=qwen3:0.6b        # 用 Ollama 的 tag，不要填 HF 的 Qwen3-0.6B
```
> ⚠️ 模型名务必用 Ollama 的 tag（`qwen3:0.6b`），不是 HF 的 `Qwen3-0.6B`，否则 `/v1/models` 对齐会 404。
> ⚠️ **base_url 务必用 `127.0.0.1` 而非 `localhost`**：部分环境 `localhost` 会解析到 IPv6 `::1`，而 Ollama 只监听 IPv4，Python 客户端会报 `Connection error`。改用 `127.0.0.1` 即可。
> ⚠️ **Ollama 服务必须在本机运行中**（`ollama serve` 或桌面客户端常驻）。若服务随上一次终端关闭而退出，Python 会报 `ConnectionRefusedError`，启动服务后再跑即可。

### 运行
```bash
pip install -r experiments/ch02/exp2-4/requirements.txt
python experiments/ch02/exp2-4/main.py                  # 全部 6 个消融变体（默认已关思考，直接出干净结果）
python experiments/ch02/exp2-4/main.py --only no_fewshot   # 只跑某变体
python experiments/ch02/exp2-4/main.py --think        # 显式开启模型原生思考（默认关闭）
python experiments/ch02/exp2-4/main.py --samples 3     # 只用前 3 条样本快速预览
```

## 一、实验目标

通过**消融（ablation）**验证一个核心观点：**提示不是"写完就完事"，而是由多个组件拼成的；某个组件到底有没有用，要拿掉它看数据，而不是凭感觉。**

- 把生产级提示拆成 4 个可独立拿掉的组件：系统角色、少样本示例、思维链引导、输出格式约束。
- 在**同一份固定测试集**上，逐个拿掉一个组件跑一遍，比较准确率。
- 掉得越多 = 该组件越关键。用数据回答"我这一堆提示词里，哪些是真的在干活"。

## 二、核心概念

- **提示工程（Prompt Engineering）**：通过设计输入文本来引导模型行为，而非改模型权重。
- **消融实验（Ablation）**：控制变量法——固定其它一切，只移除一个因素，观察指标变化。源自神经科学/深度学习，用来判断每个模块的贡献。
- **封闭标签分类**：标签空间固定且有限（本实验为 咨询/投诉/建议），模型输出易于确定性解析，适合做可复现的消融。
- **温度归零（temperature=0）**：消融要可复现，同一输入应得到稳定输出，故所有请求 temperature=0。

## 三、前置条件

- Python 3.10+（本机 `my-test/.venv` 即可）
- 依赖：`openai` + `python-dotenv`（见 `requirements.txt`）
- 一个 OpenAI 兼容端点：推荐本地 Ollama（`http://127.0.0.1:11434/v1`，务必用 127.0.0.1 而非 localhost），也可用 AMD Radeon Cloud 等真实 API；配置写在仓库根 `.env`（参考 `.env.example`）
- 联网：仅用真实 API 时需要；本地 Ollama 路径完全离线可跑

## 四、实验约束条件（跑之前必读）

1. **用真实 API 时必须配 Key（Ollama 本地路径填 `ollama` 占位即可，完全离线）**：Key 放根目录 `.env` 的 **`OPENAI_API_KEY`**，变量名固定，`.env` 已被 `.gitignore` 忽略，**切勿提交**。
2. **模型默认 `DeepSeek-V4-Flash`（AMD 免费公共模型），可换但需 API 可见**：本地路径默认 `qwen3:0.6b`。模型大小不影响本实验"相对差异"结论，但 0.6B 小模型**绝对准确率有限**——重点看"拿掉某组件后掉多少"，别纠结绝对数值。
3. **默认【关闭】模型原生思考（thinking）**：脚本默认向 Qwen3 注入 `enable_thinking:false`。原因有二——① 原生思考会吃掉 `max_tokens` 预算，让 0.6B 小模型吐不出标签（实测开着会全 0%）；② 它是独立于"提示组件"的另一维度，开着会污染消融纯度、增加随机性。只有显式加 `--think` 才会打开。
4. **温度已固定为 0** 以保证可复现；若想看方差可加 `--repeat`（本版未实现，可在 `evaluate_variant` 外包一层）。
5. **网络与限流**：免费端点限速，6 变体 × N 样本次调用，脚本已内置 0.3s 间隔，遇 429 稍等重试即可。

## 六、六个消融变体

| 变体 | 去掉的组件 | 意图 |
| :-- | :-- | :-- |
| `full` | （无，基线） | 全组件：系统角色 + 少样本 + 思维链 + 格式约束 |
| `no_system` | 系统角色 | 不告诉模型"你是谁/要做什么" |
| `no_fewshot` | 少样本示例 | 不给示范，纯靠指令 |
| `no_cot` | 思维链引导 | 不让它先推理，直接给结论 |
| `no_format` | 输出格式约束 | 不要求规范格式，自由发挥 |
| `minimal` | 全部 | 只剩一句"请对这句话分类"，最裸提示 |

### 测试集为什么要"重设计"
初版用的是 10 条直白短句，结果 6 个变体全 90%、毫无区分度——因为**任务太简单，模型不靠任何组件就能分对**，天花板封顶、无处可跌；且评分只算宽松的"标签准确率"，把格式组件的效果也抹平了。

本版做两处修正，让消融真正"有区分度"：
1. **测试集混入"陷阱样本"**：表面线索（"能不能/怎么"）会误导 naive 模型，必须按 `SYSTEM_ROLE` 的定义（咨询=询问信息/流程；投诉=表达不满/质量；建议=改进诉求）才能分对。例如"你们能不能把导出功能做成一键的？"——naive 看到"能不能"会判咨询，按定义是"改进诉求=建议"。这样**去掉系统角色 / 少样本才会掉分**。
2. **双指标评分**：同时报「标签准确率 `acc`」与「格式合规率 `fmt`」。去掉格式约束时 `acc` 几乎不变、但 `fmt` 暴跌——这才是对"格式组件有没有用"的诚实回答（它不提升对错，却决定下游能否机器解析）。

测试集：12 条中文客服短句（8 条对照 + 4 条陷阱），gold label 固定，用于算双指标。

## 七、实测现象与解读（本地 `qwen3:0.6b` · 12 样本 · 默认关思考）

> 下面数字是本机实跑（Ollama `qwen3:0.6b`，CPU）的真实值，不是理论预期。绝对数值随模型/硬件而异，**重点看相对差异**。
> ⚠️ 12 样本下，1 条样本 ≈ 8.3pp，故 ±1 样本内的差异属噪声，别过度解读；小模型在 `temperature=0` 下仍可能有轻微抖动，多跑几次看趋势。

| 变体 | 标签准确率 | Δacc | 格式合规率 | Δfmt | 去掉的组件 |
| :-- | :-- | :-- | :-- | :-- | :-- |
| `full` | 50.0% | — | 50.0% | — | （基线，无） |
| `no_system` | 58.3% | +8.3pp | 66.7% | +16.7pp | 系统角色 |
| `no_fewshot` | 16.7% | **−33.3pp** | 16.7% | −33.3pp | 少样本示例 |
| `no_cot` | 33.3% | −16.7pp | 33.3% | −16.7pp | 思维链引导 |
| `no_format` | 16.7% | −33.3pp | **0.0%** | **−50.0pp** | 输出格式约束 |
| `minimal` | 0.0% | −50.0pp | 0.0% | −50.0pp | 全部 |

### 结论（单组件消融视角）
1. **少样本（few-shot）是准确率的最大功臣**：拿掉它，标签准确率 50% → 16.7%（−33.3pp）。小模型靠"看示范"远比"听你讲道理"稳，印证了"提示工程里 few-shot 通常贡献最大"的共识。
2. **格式约束决定"下游能否机器解析"**：拿掉它，格式合规率 50% → **0%**（−50pp），但标签准确率只从 50% → 16.7%。说明格式组件**不影响"分没分对"，却决定"输出能不能被程序可靠解析"**——这正是它真正的价值所在。
3. **思维链（CoT）中等贡献**：去掉后准确率 −16.7pp，对"先推理再结论"类任务有帮助，但不如 few-shot 关键。
4. **系统角色几乎无影响**：`no_system` 反而 +8.3pp（在 ±8.3pp 单样本噪声内），本测试集下角色定义不是瓶颈——这恰好说明"你以为重要的组件，拿掉可能毫无影响"。
5. **最裸提示（minimal）直接归零**：只剩一句"请分类"时，0.6B 完全乱猜，印证"提示工程的每个组件都在干活，只是权重不同"。
6. **提示工程要"用消融验证"**：同一组件对不同指标贡献不同（格式→可解析性、few-shot→准确率）。靠数据，不靠玄学。

## 八、踩坑备注

- 未配 `OPENAI_API_KEY` 时脚本直接报错退出并提示去建 `.env`，不会发起请求。
- 标签解析取「文本中最后出现的 咨询/投诉/建议」；若模型完全跑题（输出里没有这三个词）记为解析失败、算 0 分——这本身也说明该提示"不稳"。
- `temperature=0` 下同一变体多次运行结果应一致；若波动大，多半是端点带采样或缓存，可检查 `EXTRA_BODY`。
- 中文路径下若用 shell `cd` 进实验目录失败，用绝对路径直接 `python <绝对路径>/main.py`。
- **为什么初版会"全 90%、看不出差别"**：① 测试集太简单，模型不靠任何组件就能分对，天花板封顶无处可跌；② 单一"标签准确率"评分太宽松，把格式组件的效果也抹平了。本版用「陷阱样本 + 双指标（acc/fmt）」修复，才让各组件贡献分明。若你换回简单测试集，会再次看到"全绿无区分"——那是任务太简单，不是 bug。
- **命令行参数已改为默认关思考**：`--think` 才开原生思考（见第四节第 3 条）。直接 `python main.py` 即得干净结果。
