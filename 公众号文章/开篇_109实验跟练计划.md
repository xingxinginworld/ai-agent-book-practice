# 我准备把一本 AI Agent 神书"练"一遍：109 个实验的跟练计划

> 公众号「在不确定中交付」· 在路上
> 作者：关星星（FDE · AI 交付工程师）

---

读技术书有两个层次：一种读到"原来如此"，合上书脑子里多了一点概念；另一种读到"我来试试"，合上书手上多了一点肌肉记忆。

《深入理解 AI Agent》属于后者。它不靠概念堆叠凑厚度，而是用 **109 个可动手的实验**，把 Agent 从"能聊"到"能干活"的全链路拆成一件件可以亲手验证的小事。

这篇文章做三件事：**介绍这本书和它的开源仓库**、**晒出我对全书实验的系统性盘点**、**宣告我接下来的跟练动作**。

---

## 一、为什么是这本《深入理解 AI Agent》

市面上讲 Agent 的书有两种：要么停留在"提示词模板 + 架构图"，要么直接上论文公式劝退新手。

博杰力（bojieli）的这本《深入理解 AI Agent》走了中间那条更难但更扎实的路——**以实验为骨架**。从上下文工程、记忆与知识库、工具，到 Coding Agent、多模态交互、评测、后训练、持续进化、多 Agent 协作，几乎每一节都配一个能跑的实验。

更难得的是，作者把配套代码**全部开源**了：

- 官方仓库：https://github.com/bojieli/ai-agent-book

这对想真正落地 AI Agent 的交付工程师来说，是难得的高质量"教材 + 实验台"。这也是我决定动手跟练的直接原因。

## 三、关键一步：把实验按"能不能实跑"分三档

109 个实验里，不是每个都适合现在就跑。我按**资源门槛**把它们分成三档，这也是后续跟练的优先级依据：

- **🔵 必做（75 个）**：本地轻量即可实跑，无需昂贵资源。绝大多数工程向实验都在这档，是跟练的主战场。
- **🟡 选做（13 个）**：需要外部 API / 云密钥（如 Kimi、GPT、Fish Audio 等托管服务）。资源允许时再补。
- **⚪ 观察（21 个）**：需 GPU 训练或专用硬件（如第 8 章后训练类、第 6 章机器人真机类）。我先理解原理、不实跑，避免被算力门槛卡住节奏。

资源细拆：轻量本地 75 · 需 API 密钥 13 · 需 GPU 训练 17 · 专用硬件 4。

这么一分，跟练的"可行集"立刻清晰——**先把 75 个必做实验踏踏实实跑通，就已经覆盖全书 8 成以上的工程能力。**

## 四、我的跟练计划：开源 + 连载

跟练不是闷头自嗨，我把它设计成一套可复用、可围观的公开动作：

**1. 一个开源仓库**
- 仓库名：`AI-Agent实验跟练`（GitHub）
- 以官方 `bojieli/ai-agent-book` 为基准，把每个实验改写成**精简可运行 + 中文逐行注释**版本
- 每个实验一个目录：`experiments/chXX/expX-Y/README.md`，内含：目标 → 前置 → 环境 → 分步 → 核心代码 + 注释 → 备注/踩坑 → 公众号记录要点

**2. 一套三维度标签**
- 所属章节（实验 X-Y 的 X）
- 实验分类（直觉建立 / 工程搭建 / 对照消融 / 评测构建 / 模型训练 / 复现扩展）
- 适合对象（难度档 + 资源档 + 读者角色）

**3. 大量跟练笔记连载**
- 每完成一个实验，对应一篇公众号图文：纪实 + 原理 + 收获 + 踩坑
- 目标是沉淀一套"FDE 视角的 Agent 实践手册"，既给自己留档，也给同行参考

一句话：**书是作者的，实验是大家的，但笔记和踩坑是我的——我会把它们一股脑开源、连载出来。**

## 五、已经出发：第一个单元实验 2-1

首枪没选最轻的第 1 章，而是直接上了**实验 2-1：本地 LLM 服务部署与工具调用**。

理由很实际——后续绝大多数实验都依赖一个能在本地跑起来的模型服务。先把这条"地基"打牢，后面才能跑得顺。

这个单元我已经产出了两份东西：
- 一份详细跟练 README（目标 / 观察点 / 两条路线：官方项目 + 自包含精简版 / 关键机制 / 踩坑）
- 一个自包含可运行脚本 `main.py`（基于 Ollama + Qwen3-0.6B 跑通 ReAct 工具调用，逐行中文注释）

跑通那一刻最直观的收获：**一个 0.6B 的小模型，配合正确的工具调用协议，就能完成"理解意图 → 选工具 → 调工具 → 汇总答案"的完整闭环。** 这比任何架构图都更能建立对 Agent 的直觉。
